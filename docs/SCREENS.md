# EventAT — SCREENS (prototype → production)

Every prototype screen mapped to its production route, guard, data and actions; then the email catalogue.
Rules come from `SPEC.md` (§ references), tables from `DATA-MODEL.md`.

## 0. Conventions

| Topic | Rule |
|---|---|
| Layouts | `app/(site)/` public site + client account + booking flow (`client.css`, `public.css`); `app/(wizard)/partner/registratsiya/*` (`wizard.css`); `app/(panel)/partner/*` and `app/(panel)/admin/*` (`app.css`, `admin.css`). Markup and classes are ported from the prototype screen named in each row. |
| Guards | **public** — anyone; renders the guest / client / partner header variant. **guest** — signed-in users are redirected to their home. **client** — `requireRole('client')`, own records only (404 otherwise). **partner** — `requireRole('partner')`, `partner.status ∈ {approved, deactivated}`, own partner only. **partner:wizard** — status ∈ {draft, returned, submitted}. **admin(perm)** — `requireRole('admin')` + team permission (SPEC §1.2). |
| Params | `[nomer]` = request/booking/dispute number exactly as stored (`2026-0614-ЕА`, URL-encoded). `[slug]` = partner/category/event-type slug. `[id]` = uuid. |
| Action notation | `‹Label›` → `module.fn()` → `email-key, …`. The server action lives in the route's `actions.ts` and is named `<fn>Action`; it authenticates, validates (zod), calls the domain function in a transaction, revalidates, then flashes the toast shown here. `→ /route` = navigation only. **(UI)** = client-side state only (URL params, open/close). **[new copy]** = control or text not in the prototype; build only with approved copy (SPEC D60…). |
| Toasts | The prototype's toast strings are the flash messages; they are quoted after the email keys. |
| Bell | Every client/partner page header: last 10 `notification` rows, dot = any unread; clicking an item → `notifications.markRead()` + its `href`. Admin bell = computed attention items (SPEC §4 bell rule). |
